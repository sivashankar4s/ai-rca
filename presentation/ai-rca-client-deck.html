Design Patterns · Why It's Built to Last

Strategy + Plugin Registry =
swap any backend in one file

  • 🧩
    Strategy patternThe orchestrator depends only on three interfaces — DataSource, LLM, LogAnalysis. It never knows which concrete backend is running.
  • 🔌
    Plugin registryProviders are wired at request time from config. Athena↔local file, CloudWatch↔Grafana Loki, Claude↔any model — flipped by an env var.
  • ➕
    Open for extensionA new backend = one new provider file. The orchestrator and API routes never change. Zero regression risk.
  • 🧪
    Testable by designLocal-file + fake-LLM providers mean the whole pipeline runs with no AWS, no keys — ideal for CI and demos.
# Orchestrator depends on abstractions only
class RCAOrchestrator:
  def __init__(self, data, llm, logs):
    self.data = data # DataSourceStrategy
    self.llm  = llm  # LLMStrategy
    self.logs = logs # LogAnalysisStrategy

# Registry picks concrete providers from .env
data = registry.data_source("athena")
llm  = registry.llm("anthropic")
logs = registry.log_backend("cloudwatch")

# Swap a backend? Add ONE file. Nothing else changes.

Inside the AI

The LLM runs 5 precise jobs —
each grounded in real failure data

①

Summarize failures

Reads up to 50 records; identifies failing components, exact error codes, stage clustering, and time-based bursts.

②

Generate log queries

Writes 3 targeted queries — error-code search, component + ERROR filter, and trace-ID correlation.

③

Execute & collect

Runs the queries in parallel against the configured log backend and gathers the relevant log lines.

④

RCA + grouping

Correlates records + logs into structured groups with real field values — no vague "check the logs".

⑤

Executive summary

Distills all groups into a leadership-ready paragraph, ready to paste into an incident update.

🛡

Guardrails

Prompts demand actual values (component, error_code, stage, device_id). Robust JSON parsing tolerates markdown fences.
